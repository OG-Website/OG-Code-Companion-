OG COMPANION 2.1.0
OG Web.site | Library discovery, live code examples and a program workbench

START THE APPLICATION

Extract OG Companion.zip. Open the OG Companion folder and double-click
OG Companion.exe or Start OG Companion.cmd. Python and Tcl/Tk are included.
Keep the whole folder together when copying it to a drive or sending it.

EXPLORE WHAT YOU WANT TO BUILD

Choose a language and describe your inputs, features and expected outputs.
Find libraries uses that description, or the optional keyword field above
the results. Short terms such as CSV, httpx, image, JSON or SQLite make
discovery more precise. You can enter any package name, not just a supplied
example. Python discovery searches the full downloaded PyPI name index.

The source menu offers Packages, Documentation and GitHub. Packages uses
PyPI, npm, NuGet, Maven Central, crates.io, Packagist or RubyGems where a
connector exists; other languages use public GitHub repository discovery.
GitHub mode explicitly searches public repositories for the chosen language.
Previous results and Next results browse further pages. A page size is not
a limit on the total collection: external providers have their own search
limits, rate limits and availability.

BROWSE THE DOCUMENTATION AND ITS CODE

Choose Documentation and an edition from the menu beside it. The supplied
manifest contains 837 published DevDocs editions, including language
references and third-party libraries. Refresh documentation checks for
updated editions. Edition metadata is provided by DevDocs; it doesn't
establish which version of a library is installed on your computer.

Search API topics using the keyword field, or click All API topics to browse
the complete index of that edition. Select a topic and click Get code examples.
The examples selector above the workbench lists every distinct code block
found on the loaded page. Switch between them and edit the one you want.
There is no fixed total of 30 available snippets.

For a package result, Get code examples reads its registry description,
README and available documentation sources. Code, commands, configuration
and interactive transcripts keep separate language labels. Some examples
depend on surrounding documentation or earlier definitions; a transcript
includes displayed output and isn't an executable Python script.

Load source URL accepts another public HTTPS documentation page, a raw README
or a public GitHub repository. This also works for libraries absent from a
registry connector or the documentation catalogue. A page needs readable
code blocks. Sites requiring sign-in or client-side rendering may not supply
them; choose a specific usage page or public raw README instead.

Code examples show their source address. Save all examples exports the
complete loaded collection as JSON, including code, language, source and
licence/attribution details. Source terms still apply to third-party code.
DevDocs documentation is provided by freeCodeCamp at https://devdocs.io;
individual documentation retains its original copyright and licence.

EDIT AND SAVE

Edit in the workbench, then Copy code or Save code. Undo and scrolling are
available. Save uses the displayed example's language, including .json for
JSON and .txt for transcripts. Replacing unsaved code asks for confirmation.
Selecting another library keeps your current code while changing the library
details; use Get code examples when you want that library's examples.

CLEAR, BUILD AND EXPAND

Clear search empties the description, keywords, results and example selection.
It keeps your workbench code. A cleared search cannot restore old results when
its background request finishes. Clear code starts an empty workbench; unsaved
code needs confirmation before it is cleared. Save first to keep a separate file.

Build / update code uses the supplied CSV-to-JSON foundation for matching
requests. It reads CSV headers, rejects missing or blank cells, displays valid
rows and saves them as a JSON list. This foundation works without AI.

For custom requests, start Ollama and install a suitable coding model on your
computer. Refresh models detects it. Choose Starter program for a complete
foundation or Focused snippet for one operation. Expand code starts a new
request immediately, using the current editor text. Click it again after the
request finishes to build on the latest version. Each round asks for a further
useful addition when the previous request is already implemented.

Changing What are you building? and clicking Build / update code sends the new
requirement with your existing code, without resetting the workbench. Clear code
first when you want a separate program. Keep the language selector aligned with
the existing code; a language change cannot silently convert or replace it.
Undo update restores the previous code change. Ctrl+Z also works in the editor.

The first custom request discovers installed models if none is selected.
The repeated-expansion checks used qwen2.5:3b, preferred when installed; an
existing valid model selection is retained. Other model results can differ.
A selected library and up to three
loaded examples can provide reference context. Ollama uses the local address
http://127.0.0.1:11434. Ollama and its model weights are not in this ZIP.

The application asks for all requested features, but generated code is a draft.
Python syntax is checked. Updates returning identical code, or only Python
formatting/comments, are rejected. Python updates must retain existing top-level
function and class names. One correction request is allowed for these failures.
Code exceeding 24,000 characters is rejected rather than silently shortened.
These checks do not prove that every feature or detail was preserved.
That check doesn't establish correct logic, completeness or safe execution.
Test the saved program against your requirements. Other languages need their
own runtime/compiler checks. More complex tasks may require a stronger model.

ONLINE AND OFFLINE USE

Online searches send your search text to the selected public source. Documents
you open are cached under %USERPROFILE%\.og-companion\documents for reuse.
The PyPI name index is cached in the same parent folder. First searches or
large indexes can take longer. Disable Search online registries to reuse
cached documentation and supplied teaching examples without fetching pages.
An uncached document needs online access once. There is no bulk download of
every library and no single source contains every possible program.

The 30 supplied teaching entries remain as an offline fallback. Live package
examples, the full API indexes and source-URL loading are additional routes;
their code isn't restricted to those entries. Some API pages contain no code
examples and the application reports that instead of inventing one.

No dependency is installed and no retrieved or generated code is executed by
OG Companion. Copy install copies guidance for you to review. Opening a source
in a browser is separate from the online-search setting. Custom AI requests
go to the local Ollama service. There are no account keys inside this package.

Run editable source with Python 3 and Tcl/Tk: py -3 og_companion.py
Run the source checks: py -3 -m unittest -v og_companion_tests.py
Source edits need an executable rebuild before they affect OG Companion.exe.
Catalogue and asset changes are read directly by both versions.

Ctrl+Enter searches. Ctrl+Shift+Enter builds or updates code.
To check a recipient copy from a command prompt:
"OG Companion.exe" --check-installation "%TEMP%\og-companion-check.json"
This checks the GUI, branding, source-browser controls, documentation manifest
and supplied foundation, clearing and undo without AI or internet access.

The portable executable was checked on Windows 64-bit. Copying it to another
folder was tested on the development computer; a clean second computer and
macOS/Linux/ARM64 executables haven't been verified. Saved programs need their
own language runtime and dependencies. There is no universal code guarantee.
